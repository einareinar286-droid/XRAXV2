# 徐燃安巡业务、权限与安全 Spec

**文档编号：** SPEC-BIZ-001
**状态：** 规格冻结候选；实现与测试结论为阻塞/待证
**依赖：** `00-现状证据与边界.md`、`docs/三模块开发规格与提示词.md`

## 1. 业务目标与成功标准

安全监察部可上报隐患并交办；市场营销部只能在受办范围内提交整改；安全监察部在整改提交后可复核闭环或退回；高管只读。成功不是“页面上有按钮”，而是每一次读取和写入均经服务端 token、角色、部门范围、状态及版本校验，并形成可追溯审计证据。

## 2. 角色、数据范围与权限矩阵

| 角色 | 代码标识 | 数据范围 | 允许动作 | 禁止动作 |
| --- | --- | --- | --- |
| 安全监察巡检/复核人员 | `SAFETY_INSPECTOR` | 本人创建、职责范围内或被授权的隐患 | 上报、查询、交办、复核、退回 | 跨范围读取；直接重开；绕过审计闭环 |
| 安全监察管理员 | `SAFETY_ADMIN` | 跨部门查询及制度授权范围 | 上述动作、配置、留痕重开 | 绕过审计；无制度依据的重开 |
| 市场营销整改人员 | `MARKETING_RECTIFIER` | 被交办至本人或本部门，且在 token 受办范围内的隐患 | 查询、提交整改说明及佐证 | 创建、交办、复核、退回、闭环、处理非受办隐患 |
| 高管 | `EXECUTIVE_READONLY` | 授权范围内统计、重大隐患和闭环进度 | 只读查询 | 任意写操作、附件越权读取 |

服务端必须忽略客户端传入的角色、部门、操作者、状态和数据范围。前端路由守卫、按钮显隐和 Mock 角色切换只能改善体验，不能形成授权依据。

## 3. 状态机与责任人

| 当前状态 | 展示文案 | 操作 | 前置条件 | 操作者 | 下一状态 | 服务端拒绝条件 |
| --- | --- | --- | --- | --- | --- | --- |
| `REPORTED` | 待交办 | 交办 | 隐患存在、有效整改对象、版本匹配 | `SAFETY_INSPECTOR` 或 `SAFETY_ADMIN` | `ASSIGNED` | 非安全角色、跨数据范围、无受办对象、版本冲突 |
| `ASSIGNED` | 待整改 | 提交整改 | 本人/本部门受办、整改内容和佐证合格、版本匹配 | `MARKETING_RECTIFIER` | `RECTIFICATION_SUBMITTED` | 非受办人、非市场角色、附件或内容不合格、版本冲突 |
| `RECTIFICATION_SUBMITTED` | 待复核 | 复核闭环 | 职责范围内、复核结论为通过、版本匹配 | `SAFETY_INSPECTOR` 或 `SAFETY_ADMIN` | `CLOSED` | 非安全角色、复核证据不足、版本冲突 |
| `RECTIFICATION_SUBMITTED` | 待复核 | 整改退回 | 职责范围内、退回原因必填、版本匹配 | `SAFETY_INSPECTOR` 或 `SAFETY_ADMIN` | `REJECTED` | 非安全角色、退回原因缺失、版本冲突 |
| `REJECTED` | 整改退回 | 再次提交整改 | 本人/本部门受办、补充内容合格、版本匹配 | `MARKETING_RECTIFIER` | `RECTIFICATION_SUBMITTED` | 非受办人、非法附件、版本冲突 |
| `CLOSED` | 已闭环 | 按制度留痕重开 | 有制度依据、重开原因必填、版本匹配 | `SAFETY_ADMIN` | `REPORTED` | 普通用户、缺失制度依据、版本冲突 |

`CLOSED` 对普通用户不可编辑；不新增直接删除隐患能力。每一次状态变化必须在同一服务端事务或等效原子操作中写入审计事件。

## 4. 数据契约与留存

### 4.1 `Issue`

| 字段 | 规则 |
| --- | --- |
| `id` | 服务端生成，不接受客户端覆盖 |
| `title` | 必填，去首尾空白后 2–100 字符 |
| `category` | 必填，受控枚举，由服务端维护 |
| `severity` | 必填，受控枚举；`isMajor` 与严重等级由服务端规则校验 |
| `isMajor` | 布尔值；重大隐患需要更高可见性，不改变基础状态机 |
| `description` | 必填，1–2000 字符 |
| `location` | 必填，1–200 字符；不得在客户端日志中写入精确敏感坐标 |
| `attachments` | 附件元数据数组，不保存公开可猜测 URL |
| `status` | 仅服务端状态机更新 |
| `reporter`、`assignee` | 服务端从 token、交办记录或目录服务写入 |
| `departmentScope` | 服务端根据职责和受办关系计算 |
| `deadline` | 交办前必填，使用带时区的 ISO 8601 时间 |
| `createdAt`、`updatedAt` | 服务端生成 |
| `version` | 正整数；任一写操作必须匹配当前版本 |

### 4.2 `Rectification`

| 字段 | 规则 |
| --- | --- |
| `issueId` | 必填，关联存在且允许整改的隐患 |
| `note` | 必填，1–2000 字符 |
| `attachments` | 至少满足整改规则的受控附件元数据；不得由客户端直接引用外部公开 URL |
| `submittedBy`、`submittedAt` | 服务端从 token 和服务端时间写入 |
| `idempotencyKey` | 每次提交必填；同一操作者、同一业务动作、同一键只能成功一次 |

### 4.3 `AuditEvent`

`AuditEvent` 最少包含 `id`、`entityType`、`entityId`、`action`、`fromStatus`、`toStatus`、`actorUid`、`actorRole`、`occurredAt`、`requestId`、`payloadSummary`。审计记录仅由服务端追加写入，不向客户端开放直接创建、修改或删除。`payloadSummary` 不得包含 token、密钥、完整敏感附件 URL 或不必要的个人信息。

### 4.4 附件

- 附件须使用私有存储，并通过服务端按当前身份和实体授权生成短时受控下载。
- 文件类型、单文件大小、文件数、总大小由服务端白名单和配置限制；具体阈值接入目标工程后固化，并记录在部署配置与测试证据中。
- 每次上传、绑定、下载授权失败和越权拒绝应产生可审计事件或安全日志，日志不得泄露访问凭证。
- 业务数据、整改记录和审计保留期限应由企业制度、数据分类和部署环境共同确定；当前缺少制度与部署资料，留存期限为阻塞/待证。

## 5. 服务接口与错误语义

所有方法使用服务层/云对象统一调用；真实实现与 Mock 必须保持同名方法、字段含义和错误码语义。响应至少携带 `requestId`；正常业务错误不得暴露堆栈、内部路径、token 或数据库细节。

| 方法 | 目的与输入 | 成功输出 | 授权与状态条件 |
| --- | --- | --- | --- |
| `getCurrentUser()` | 无客户端角色输入 | `uid`、角色、部门范围、展示信息 | 从有效 token 解析 |
| `listIssues(filters)` | 分页、状态、范围内筛选 | 数据数组、分页游标/页码 | 仅返回调用者范围内数据 |
| `getIssue(id)` | 隐患 ID | `Issue` 详情及允许展示的数据 | 服务端实体级授权 |
| `reportIssue(payload)` | 标题、分类、等级、描述、位置、附件元数据、幂等键 | 新建 `Issue`、首条审计、`requestId` | 安全角色；写入 `REPORTED` |
| `assignIssue(id, payload)` | 受办对象、截止时间、说明、`version`、幂等键 | 更新后的 `Issue` 与审计 | 仅 `REPORTED`，安全角色且范围匹配 |
| `submitRectification(id, payload)` | 整改说明、附件元数据、`version`、幂等键 | `Rectification`、更新后的 `Issue` 与审计 | 仅 `ASSIGNED` 或 `REJECTED`，市场受办范围 |
| `reviewIssue(id, decision)` | `decision` 为 `CLOSED` 或 `REJECTED`、复核说明、`version`、幂等键 | 更新后的 `Issue` 与审计 | 仅 `RECTIFICATION_SUBMITTED`，安全角色且范围匹配 |
| `listAuditEvents(id)` | 隐患 ID、分页参数 | 已脱敏的审计列表 | 安全范围或明确授权的只读范围；不返回敏感附件凭证 |

| 错误码 | HTTP/调用语义 | 客户端可展示含义 | 记录要求 |
| --- | --- | --- | --- |
| `AUTH_REQUIRED` | token 缺失、失效或无法解析 | 登录已失效，请重新登录 | 记录 requestId 和原因类别 |
| `ACCESS_DENIED` | 角色不具备动作权限 | 无此操作权限 | 记录角色、动作和实体 ID |
| `SCOPE_DENIED` | 部门、职责或受办范围不符 | 不在您的处理范围内 | 记录范围校验拒绝 |
| `STATE_CONFLICT` | 当前状态不允许该动作 | 当前状态已变化，请刷新后重试 | 记录当前状态与期望动作 |
| `VERSION_CONFLICT` | 版本不匹配 | 数据已更新，请刷新后重试 | 记录版本冲突，不记录敏感内容 |
| `IDEMPOTENCY_REPLAY` | 同一幂等键重复提交 | 操作已受理，请勿重复提交 | 返回首次结果或稳定重放结果 |
| `VALIDATION_FAILED` | 输入、枚举、长度或附件规则不合法 | 请检查填写内容或附件 | 记录字段类别，不记录敏感全文 |
| `ATTACHMENT_DENIED` | 文件不合规或读取未经授权 | 附件不可用或无权访问 | 记录附件 ID 与原因类别 |
| `INTERNAL_ERROR` | 未预期服务端失败 | 服务暂不可用，请稍后重试 | 仅服务端保存详细诊断，客户端仅见 requestId |

## 6. 安全与并发要求

1. 每个读写请求必须从服务端 token 解析身份，并在实体加载后重新计算角色、部门、受办范围和允许状态。
2. 所有状态迁移采用白名单；不得依据前端传入的 `fromStatus`、角色或部门直接决定结果。
3. 写操作同时要求 `version` 与 `idempotencyKey`：前者防止旧页面覆盖，后者防止连点与网络重试造成重复业务动作。
4. 身份、范围、状态、版本、审计写入应在同一原子边界内处理；无法支持事务时，必须以条件更新保证状态与版本不可被并发绕过。
5. 重开只有 `SAFETY_ADMIN` 可按制度执行，必须保留原闭环记录、制度依据、原因、操作者与审计；不得覆盖历史审计。
6. 日志、截图、测试夹具和提交记录不得保存密码、token、私有下载凭证、AppID 或密钥。

## 7. 安全验收证据

截至 2026-08-02，M1 Mock 适配器测试已通过 5/5，覆盖正向闭环、退回后再次整改、市场部在受办前的读取拒绝、可见范围分页及幂等重放/冲突；该证据只覆盖本地 Mock，不构成服务端安全结论。

| 控制项 | 最低证据 | 当前结论 |
| --- | --- | --- |
| Mock 闭环、退回、范围和幂等 | `node --test tests/issues/mock-adapter.test.mjs` 输出 | 部分通过：5/5 覆盖正向路径、退回再整改、受办前读取拒绝、列表范围及幂等；生产安全控制仍待证 |
| token 鉴权与伪造角色拒绝 | 服务端自动化测试输出或受控集成测试记录 | 阻塞/待证 |
| 部门与受办范围校验 | 跨部门、未受办实体的拒绝测试 | 阻塞/待证 |
| 状态机白名单 | 非法跳转及闭环后编辑的拒绝测试 | 阻塞/待证 |
| 幂等与乐观锁 | 重复提交、并发提交与旧版本冲突测试 | 阻塞/待证 |
