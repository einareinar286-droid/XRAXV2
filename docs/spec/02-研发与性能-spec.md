# 徐燃安巡研发与性能 Spec

**文档编号：** SPEC-ENG-001
**状态：** 规格冻结候选；工程、构建与性能数据为阻塞/待证
**依赖：** `01-业务权限与安全-spec.md`

## 1. 架构边界与适配器策略

前端业务页面只依赖 `IssueService` 服务层，不得直接把内存 Mock 状态、云对象调用或公司 API 调用散落在页面与组件中。下列接口及错误语义必须保持一致：

```text
getCurrentUser()
listIssues(filters)
getIssue(id)
reportIssue(payload)
assignIssue(id, payload)
submitRectification(id, payload)
reviewIssue(id, decision)
listAuditEvents(id)
```

| 层级 | 职责 | 允许依赖 | 禁止事项 |
| --- | --- | --- | --- |
| 页面/组件 | 收集输入、展示状态、调用服务层、显示稳定错误信息 | `IssueService`、UI 状态 | 直接决定生产权限、直连数据库、拼接附件公开 URL |
| 服务接口 | 定义统一方法、请求/响应模型和错误码 | 领域模型、适配器 | 暴露不同后端的专有错误给页面 |
| Mock 适配器 | 开发演示、可重复测试和错误态模拟 | 固定测试数据、接口契约 | 作为生产真实数据源或权限边界 |
| uniCloud/公司 API 适配器 | token 调用、服务端授权、私有附件和审计 | 后端契约 | 接收前端角色/部门作为可信授权依据 |
| 服务端领域层 | 实体加载、授权重算、状态转换、审计、条件更新 | token、数据存储、私有文件存储 | 向客户端开放审计直改删 |

### 1.1 运行时选择

- 开发与演示可通过明确的、非生产构建配置选择 Mock 适配器。
- 生产构建必须使用 uniCloud/公司 API 适配器，并移除或隔离真实身份的演示角色切换入口。
- 两种实现必须返回同一业务字段和同一错误码；新增后端字段不得成为页面绕过服务层的理由。
- 当前没有工程配置、构建脚本或环境文件，具体开关位置及生产移除验证为阻塞/待证。

## 2. 数据兼容、迁移与回滚

### 2.1 兼容原则

1. 隐患领域独立于既有履职领域。不得为了隐患闭环把 `Issue`、`Rectification`、`AuditEvent` 混入履职 schema 或改写 `src/services/duty.js`。
2. 对现有演示数据，`待整改` 映射 `ASSIGNED`，`待复核` 映射 `RECTIFICATION_SUBMITTED`，`已闭环` 映射 `CLOSED`；其他状态不得擅自推断。
3. 兼容处理应保留来源、迁移时间、执行版本和失败记录，且可重复执行而不重复创建审计事件。
4. 每次迭代须执行既有履职页面、`SAFETY_ADMIN` 查询和小程序构建回归；因当前工程缺失，这三项均为阻塞/待证。

### 2.2 受控变更

任何公共 API、schema、角色权限或状态机调整必须先登记 `docs/spec/06-需求变更记录.md`，并完整提供：

| 必填项 | 说明 |
| --- | --- |
| 影响范围 | 受影响前端页面、服务接口、云对象、数据集合、履职能力、测试和文档 |
| 兼容策略 | 新旧调用、字段缺失、存量状态和附件的处理方式 |
| 迁移方案 | 执行主体、顺序、幂等方式、备份点、监测指标和失败处置 |
| 回滚方案 | 触发阈值、停止写入方式、恢复目标版本、数据补偿和责任角色 |
| 验收方案 | 自动化测试、集成测试、构建、真机或受控试运行的证据位置 |
| 审批责任 | 业务、研发、安全、运维/发布的责任角色和批准时间 |

无上述信息的变更不得进入 M2 及之后的试运行候选。

## 3. 测试与构建策略

| 验证层级 | 最低覆盖 | 推荐证据 | 当前结论 |
| --- | --- | --- |
| 领域单元测试 | 状态机、字段校验、错误码映射、幂等/版本规则 | 自动化测试输出与覆盖范围说明 | 阻塞/待证 |
| 服务端授权测试 | token 身份、角色越权、部门越权、伪造角色、附件越权 | 服务端测试输出与拒绝码 | 阻塞/待证 |
| 集成测试 | 正向闭环、审计追加、私有下载、重复提交和弱网重试 | 受控环境请求记录、审计查询结果 | 阻塞/待证 |
| UI 验收 | 角色可见性、加载/空/失败/成功状态、错误提示 | 截图、录屏、组件测试或操作记录 | 阻塞/待证 |
| 回归测试 | 履职页面、管理员查询、微信小程序构建 | 构建日志与回归清单 | 阻塞/待证 |
| 发布验证 | 安全、性能、兼容、审计与回滚演练 | M5 门禁记录 | 阻塞/待证 |

### 3.1 自动化测试最低要求

- 正确完成上报、交办、整改提交、复核闭环，以及退回后再次整改。
- 市场营销部处理未受办隐患、高管发起写操作、客户端伪造角色/部门均被服务端拒绝。
- 非法状态跳转、重复整改、闭环后普通编辑和旧版本写入均被拒绝。
- 每次状态变化产生一条追加式 `AuditEvent`；客户端不能直接改删审计。
- 未授权附件读取被拒绝；授权访问不泄露长期公开链接。
- Mock 与真实适配器契约测试使用同一组场景与错误码断言。

测试失败、未执行或因环境缺失无法执行时，必须在 `docs/开发日志.md` 记录真实命令、输出摘要、影响和下一步；不得用“代码已写”替代通过证据。

## 4. 性能与弱网规范

### 4.1 指标

| 类别 | 目标 | 实现要求 | 未达标处置 |
| --- | --- | --- | --- |
| 常规交互 | 真机目标 60 FPS | 滚动、切换、提交反馈不阻塞输入 | 记录设备和场景；定位长列表、图片或动画；启用降级方案 |
| 内容转场 | 180–300 ms，默认 220 ms | 仅 `transform`、`opacity`；克制缓出 | 移除高代价效果或缩短到不影响连贯性 |
| 首屏 | 只加载必要数据 | 不预取无关列表、附件原图或统计 | 延迟非必要请求，记录加载链路 |
| 长列表 | 分页或增量渲染 | 固定渲染窗口，避免一次性大数据集 | 减小页长、启用分页/虚拟化方案 |
| 图片 | 压缩、缩略图、懒加载 | 列表禁止直接加载原图 | 限制分辨率，失败时给重试与占位 |
| 写操作 | 防连点、冲突处理 | 按钮防重复、携带幂等键与 `version` | 显示稳定冲突提示并刷新数据 |
| 弱网/失败 | 无白屏、可恢复 | 超时、离线、接口失败均可重试 | 保留输入草稿的方案须经过安全评审 |

### 4.2 禁止事项

- 不动画 `width`、`height`、`top`、`left`，不使用大面积 `filter`、模糊或重阴影动画。
- 不强行覆盖 `uni.switchTab` 或原生导航动画；仅在页面展示/组件挂载时做轻量内容过渡。
- 不在提交成功前乐观显示闭环结果；必须以服务端返回的实体版本为准。
- 不因为优化引入来路不明的大型 UI、动效或监测依赖。新增依赖前必须说明用途、包体影响和无依赖替代方案。

### 4.3 测量方法与记录

必须使用微信开发者工具和至少一台真机，分别记录下列场景：Tab 切换、待办到详情、随手拍提交到详情、整改提交到待复核、复核到闭环、长列表滚动、图片加载、网络失败重试。

| 记录字段 | 要求 |
| --- | --- |
| 环境 | 微信开发者工具版本或真机型号、系统版本、小程序基础库/运行环境 |
| 构建版本 | Git 提交、构建时间、适配器类型、测试数据规模 |
| 场景 | 起止页面、操作步骤、网络条件、是否含图片/长列表 |
| 指标 | 帧率/性能面板观察、首屏关键请求、卡顿或白屏情况、交互响应 |
| 结论 | 通过、阻塞或不通过；不通过必须描述可复现条件和降级/修复措施 |

没有以上记录不得宣称满足 60 FPS。

## 5. 接入与发布前检查

1. 将目标工程接入后，先核对 `README.md`、构建脚本、页面路由、服务层、云对象、履职部署说明与本 Spec 的差异。
2. 对差异建立变更记录；不得直接改写共享状态机或权限含义。
3. 先以 Mock 跑通可重复闭环和错误态，再接入真实 token、范围授权、审计和私有附件。
4. 接入真实后端前执行迁移演练与回滚演练；回滚不能删除审计或丢失已经受理的整改证据。
5. M5 仅在功能、授权、安全、性能、兼容、日志/审计、履职回归全部有证据通过后才允许进入试运行。
