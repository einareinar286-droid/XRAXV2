# 徐燃安巡需求变更记录

**文档编号：** SPEC-CHG-001
**状态：** 受控记录模板
**适用范围：** 公共 API、schema、角色权限、状态机、附件访问规则、性能门槛、发布流程及本期范围的变更。

## 1. 变更控制规则

1. 未登记、未评估或未批准的公共契约变更不得实施、合并、部署或进入试运行。
2. 每条变更必须说明为什么需要改、影响什么、如何迁移、如何回滚、如何验收以及谁负责；“顺手改一下”不构成工程方案。
3. 涉及状态机、角色或 schema 的变更须由业务、研发与安全责任角色共同确认；涉及发布与回滚的变更还须有运维/发布责任角色确认。
4. 任何变更不得删除历史审计、绕过 token 授权、将私有附件公开化，或破坏既有履职能力。
5. 变更实施后，更新相关 Spec、追溯矩阵、验收用例和 `docs/开发日志.md`；证据不足时结论保持阻塞。

## 2. 变更单模板

复制以下模板创建新记录。变更编号采用 `CHG-YYYYMMDD-序号`。

---

### CHG-YYYYMMDD-序号｜变更标题

| 字段 | 内容 |
| --- | --- |
| 状态 | 提出 / 评估中 / 已批准 / 实施中 / 已验证 / 已拒绝 / 已回滚 |
| 提出人及日期 | 责任角色、姓名/账号标识、日期 |
| 变更类型 | 范围 / 公共 API / schema / 角色权限 / 状态机 / 附件 / 性能 / 发布 |
| 关联需求 | `RQ-xx`、`UC-xx`、里程碑、缺陷或审计事件 |
| 变更原因 | 业务、合规、安全、性能、兼容或缺陷原因；描述可验证事实 |
| 变更内容 | 新旧规则对比；禁止只写“优化”或“调整” |
| 影响范围 | 前端、服务层、云对象/API、数据、附件、履职、测试、文档、部署和用户角色 |
| 风险等级 | 高 / 中 / 低，以及不实施风险和实施风险 |
| 兼容策略 | 新旧客户端、存量数据、状态、附件和调用方的处理规则 |
| 迁移方案 | 执行步骤、幂等方式、备份点、顺序、责任人、成功/失败判据 |
| 回滚方案 | 触发条件、停止写入、恢复版本、数据补偿、审计保留与责任人 |
| 验收方案 | 必跑的 `UC-xx`、构建、真机、审计、性能和回滚演练证据 |
| 审批记录 | 业务、研发、安全、运维/发布责任角色；结论和日期 |
| 实施记录 | Git 提交、部署版本、执行时间、实际结果与异常 |
| 验证结论 | 通过 / 不通过 / 阻塞；证据位置和遗留风险 |
