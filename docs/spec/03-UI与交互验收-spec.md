# 徐燃安巡 UI 与交互验收 Spec

**文档编号：** SPEC-UX-001
**状态：** M1 页面实现与 H5 视口核验部分通过；真机与生产授权验证仍为阻塞/待证
**依赖：** `01-业务权限与安全-spec.md`、`02-研发与性能-spec.md`

## 1. 体验目标与边界

在不改变登录鉴权、服务端权限、状态机、schema 和接口契约的前提下，让现场人员在 3 秒内理解当前状态、是否重大、责任部门、截止时间、证据是否齐全以及自己可执行的下一步动作。

本 Spec 规定验收结果，不替 UI 团队做具体颜色、布局或组件库选择。界面保持绿色安全管理基调；重大隐患使用稳定、清晰的危险语义，不得闪烁、抖动或恐吓式红色轰炸。

## 2. 关键页面验收

| 页面/场景 | 必须展示 | 角色动作 | 通过标准 |
| --- | --- | --- | --- |
| 待办/隐患列表 | 状态、重大标识、责任部门、截止时间、更新时间、加载/空/失败 | 按服务端返回权限显示入口 | 用户无需进入详情即可识别优先级和下一步归属 |
| 随手拍/隐患上报 | 标题、分类、等级、描述、位置、图片、必填提示、上传与提交状态 | `SAFETY_INSPECTOR`、`SAFETY_ADMIN` 可提交 | 校验、上传失败重试和成功回流明确；不重复提交 |
| 隐患详情 | 状态时间线、责任部门、截止时间、整改与复核证据、审计摘要、当前操作区 | 仅显示该角色被服务端允许的操作 | 状态、责任和下一步动作清晰；敏感附件不显示可猜测链接 |
| 整改提交 | 退回原因（如有）、整改说明、附件、提交状态 | 仅受办范围 `MARKETING_RECTIFIER` | 未受办人员无可点击提交入口；成功后同步为待复核 |
| 复核结论 | 整改信息、通过/退回结论、原因输入、提交状态 | `SAFETY_INSPECTOR`、`SAFETY_ADMIN` 在待复核状态操作 | 非待复核不显示可执行闭环；退回原因缺失时不得提交 |
| 我的/登录状态 | 当前用户、角色、部门范围、会话失效和重新登录入口 | 全角色 | 不提供生产真实角色切换入口；会话失效可理解且可恢复 |

## 3. 角色可见性

| 动作 | `SAFETY_INSPECTOR` | `SAFETY_ADMIN` | `MARKETING_RECTIFIER` | `EXECUTIVE_READONLY` |
| --- | --- | --- | --- |
| 上报 | 可见，服务端确认 | 可见，服务端确认 | 不可见 | 不可见 |
| 交办 | 仅 `REPORTED` 且范围内可见 | 仅 `REPORTED` 且范围内可见 | 不可见 | 不可见 |
| 提交整改 | 不可见 | 不可见 | 仅 `ASSIGNED`/`REJECTED` 且受办范围内可见 | 不可见 |
| 闭环/退回 | 仅 `RECTIFICATION_SUBMITTED` 且范围内可见 | 同左 | 不可见 | 不可见 |
| 按制度重开 | 不可见 | 仅 `CLOSED` 且具制度授权时可见 | 不可见 | 不可见 |
| 编辑已闭环隐患 | 不可见 | 仅走重开流程，不直接编辑 | 不可见 | 不可见 |

前端隐藏按钮不等于授权；服务端拒绝后，界面须显示不泄露内部细节的错误提示。对可读但无写权限的用户，可在操作区显示简短归属说明，不应显示可点击的假按钮。

## 4. 全状态交互验收

| 状态 | 必须反馈 | 通过标准 |
| --- | --- | --- |
| 加载 | 骨架屏或明确加载提示 | 不出现无意义空白；加载不遮蔽必要的返回/取消操作 |
| 空数据 | 空态说明与权限范围提示 | 不将“无数据”“无权限”“网络失败”混为同一种空态 |
| 网络失败 | 错误说明、重试、保留安全的输入状态 | 重试不会重复提交；不暴露服务端内部错误 |
| 无权限 | 简短原因与下一步归属 | 不显示敏感数据、附件凭证或内部权限细节 |
| 附件上传中 | 进度或明确处理中状态、取消/重试规则 | 不允许未完成附件被当作成功佐证 |
| 附件上传失败 | 失败原因类别、重试或移除入口 | 不丢失已填写的非敏感表单内容；不显示私有访问凭证 |
| 表单校验失败 | 字段级提示和提交阻止 | 与服务端校验语义一致，不只依赖前端校验 |
| 提交成功 | 成功反馈、最新状态、列表/详情同步 | 以服务端返回状态与版本为准，不能本地伪造成功 |
| 状态冲突 | 刷新提示、重新加载最新数据 | 不覆盖他人已提交的整改或复核结果 |

## 5. 动效与可用性验收

| 项目 | 规则 | 验收方法 |
| --- | --- | --- |
| 内容转场 | 180–300 ms，默认 220 ms；只使用 `transform`、`opacity` 与克制缓出 | 检查样式/实现与开发者工具性能面板 |
| 原生导航 | 不强行覆盖 `uni.switchTab` 或平台页面导航 | Tab 切换、返回、前进均遵循平台行为，无双重动画 |
| 列表与卡片 | 状态切换、增删或入场不阻塞滚动和点击 | 长列表滚动与状态更新观察 |
| 低性能降级 | 弱机或减少动画偏好下退化为淡入或无动画 | 指定设备或偏好下验证输入和滚动正常 |
| 图片 | 缩略图、懒加载、失败占位与预览不阻塞列表 | 有图片和无图片列表均检查 |
| 禁止效果 | 不动画 `width`、`height`、`top`、`left`；不做重滤镜、模糊和大面积阴影动画 | 样式审查与真机观察 |

## 6. 真机体验与帧率验收

至少一台真机与微信开发者工具必须覆盖：Tab 切换、待办→详情、随手拍提交→详情、整改提交→待复核、复核→闭环。每项记录环境、构建版本、数据规模、网络条件、观察指标、结论和问题。

| 结论 | 判定 |
| --- | --- |
| 通过 | 无白屏、无阻塞输入、状态同步正确；性能观察符合 60 FPS 目标或无可感知卡顿 |
| 不通过 | 出现可复现白屏、明显卡顿、错误角色动作、状态不同步或异常动画 |
| 阻塞 | 没有可运行工程、微信开发者工具、真机、目标构建或测试账号/数据 |
