# 徐燃安巡里程碑与发布门禁

**文档编号：** SPEC-REL-001
**状态：** 计划基线；所有实现型退出证据为阻塞/待证
**责任角色：** 模块 02 维护；模块 01、模块 03、业务/发布责任角色补证

## 1. 里程碑总览

| 里程碑 | 名称 | 目标 | 不包含 |
| --- | --- | --- | --- |
| M0 | 基线、共享契约与风险冻结 | 固定范围、状态机、角色、接口和验收口径 | 业务代码、UI 批量实现、schema 变更 |
| M1 | Mock 闭环与前端角色体验 | Mock 下可重复演示正确闭环和错误态 | 真实登录、生产授权、真实附件存储 |
| M2 | uniCloud/公司 API 授权与审计 | 真实 token 授权、范围校验、审计和私有附件 | AI 审核、订阅消息及范围外能力 |
| M3 | UI、动效与性能优化 | 角色可见性、全状态反馈、性能友好动效 | 改写服务端状态机或权限 |
| M4 | 安全、性能、兼容与回归验收 | 安全/性能/兼容/履职回归证据齐全 | 无证据的试运行 |
| M5 | 试运行准备与发布门禁 | 完成变更、回滚、监控和发布决策 | 跳过门禁直接上线 |

## 2. M0：基线、共享契约与风险冻结

| 项目 | 内容 |
| --- | --- |
| 目标 | 用实际工程核对或记录缺失，冻结本期范围、四角色、五状态、核心字段、服务接口和验收口径。 |
| 范围外事项 | 业务功能开发、视觉批量改造、公共 API/schema 落地修改。 |
| 入口条件 | 已获得协同规格与模块提示词；目标工程可用时需可读取源码、日志、部署说明。 |
| 依赖 | 业务责任人确认本期仅含隐患闭环基础；模块 01/03 接受共享状态机。 |
| 交付物 | 三类 Spec、里程碑、用例与追溯矩阵、变更记录模板、风险清单。 |
| 验收用例 | UC-01 至 UC-13 的用例框架已建立；所有缺失证据标为阻塞。 |
| 退出标准 | 无互相冲突的角色、状态机、接口或性能口径；范围外事项明确；风险责任角色明确。 |
| 风险与责任角色 | 规格脱离真实代码为高风险；模块 02 记录差异，模块 01 提供源码/日志证据。 |

## 3. M1：Mock 闭环与前端角色体验

| 项目 | 内容 |
| --- | --- |
| 目标 | 在统一 `IssueService` Mock 契约下演示上报、交办、整改、复核闭环/退回与错误态。 |
| 范围外事项 | 将 Mock 角色或内存数据作为生产权限；接入真实账号、云端附件或真实审计。 |
| 入口条件 | M0 退出；Mock 服务层接口、固定测试用户和隔离测试数据已就绪。 |
| 依赖 | 模块 01 的领域模型/Mock 适配器；模块 03 的页面动作可见性与状态反馈。 |
| 交付物 | Mock 契约测试、演示脚本、正向闭环与常见拒绝场景记录、开发日志。 |
| 验收用例 | UC-01、UC-05、UC-06、UC-10、UC-11 的 Mock 版；角色显隐可作体验验证但不是安全证据。 |
| 退出标准 | 正向路径可重复；非法状态与重复提交有稳定错误码；页面不提供无权限假按钮；Mock 标识对开发/演示清晰。 |
| 风险与责任角色 | Mock 被误用于生产为高风险；模块 01 负责构建隔离，模块 03 负责演示入口不误导，模块 02 验收标注。 |

## 4. M2：uniCloud/公司 API 授权、审计与私有附件

| 项目 | 内容 |
| --- | --- |
| 目标 | 使用服务端 token 解析身份，完成实体级角色/部门范围授权、状态迁移、并发防护、审计与私有附件。 |
| 范围外事项 | 前端信任角色切换、公开附件 URL、客户端直改审计、没有制度依据的重开。 |
| 入口条件 | M1 退出；真实后端接口、测试环境、账号与部门/受办测试数据可用；变更单完整。 |
| 依赖 | uniCloud/公司 API、身份目录、私有文件存储、审计存储、模块 01 服务端实现。 |
| 交付物 | 服务端授权测试、审计查询记录、附件授权测试、迁移/回滚方案、接口契约验证。 |
| 验收用例 | UC-02、UC-03、UC-04、UC-05、UC-06、UC-07、UC-08。 |
| 退出标准 | 所有服务端拒绝类用例有稳定错误码和真实输出；每次状态变化有追加审计；附件不能越权读取；生产构建无真实角色切换。 |
| 风险与责任角色 | 错配部门范围或附件泄露为高风险；模块 01 负责技术控制，安全责任人复核，模块 02 收集证据。 |

## 5. M3：UI、动效与性能优化

| 项目 | 内容 |
| --- | --- |
| 目标 | 完成关键页面的角色可见性、加载/空/失败/成功反馈、性能友好动效和弱机降级。 |
| 范围外事项 | 修改状态机、服务端权限、schema、接口字段含义。 |
| 入口条件 | M1 已具备可运行 Mock；M2 接口或等效契约可供页面调用。 |
| 依赖 | 模块 03 页面实现；模块 01 服务层返回稳定错误码与权限信息；真实/Mock 测试数据。 |
| 交付物 | 页面和组件改动清单、动效参数表、性能测量记录、全状态截图或录屏。 |
| 验收用例 | UC-09、UC-10、UC-11、UC-12，以及 UC-01 的 UI 路径。 |
| 退出标准 | 用户能在 3 秒内识别状态、责任部门、截止时间和下一步；动效符合 180–300 ms 与属性限制；真机测量已有结论。 |
| 风险与责任角色 | 重图片/重动效导致弱机掉帧为中风险；模块 03 负责降级，模块 02 核验记录完整性。 |

## 6. M4：安全、性能、兼容与回归验收

| 项目 | 内容 |
| --- | --- |
| 目标 | 对完整链路执行安全、性能、兼容、构建、履职和错误恢复回归，形成可签署结论。 |
| 范围外事项 | 用“未测但预计没问题”代替证据；在测试失败时进入试运行。 |
| 入口条件 | M2、M3 退出；测试环境接近发布配置；测试账号和数据隔离。 |
| 依赖 | 自动化测试、微信开发者工具、至少一台真机、履职基线、构建工具、发布责任角色。 |
| 交付物 | 完整 UC-01–UC-13 结果、构建日志、履职回归记录、性能/弱网记录、风险清单和阻塞项。 |
| 验收用例 | UC-01–UC-13 全量执行。 |
| 退出标准 | 关键安全用例零阻塞；性能与兼容有真实结论；履职回归通过；遗留风险有业务/安全负责人书面接受。 |
| 风险与责任角色 | 只做前端演示而未测服务端为高风险；模块 01、03 负责证据，模块 02 汇总，业务与安全责任人决定是否接受风险。 |

## 7. M5：试运行准备与发布门禁

| 项目 | 内容 |
| --- | --- |
| 目标 | 确保上线前配置、权限、回滚、审计、监控和交接齐备，并以证据决定是否可试运行。 |
| 范围外事项 | 绕过发布门禁、未审批的公共契约变更、未演练的迁移/回滚。 |
| 入口条件 | M4 退出；所有变更单关闭或有批准的风险接受；发布版本可定位至 Git 提交。 |
| 依赖 | 发布环境、运维/发布责任人、安全责任人、业务验收人、回滚权限和监控能力。 |
| 交付物 | 发布检查单、配置核验、回滚演练记录、门禁结论、试运行观察项与责任人。 |
| 验收用例 | 发布门禁 G1–G7；高风险变更须核对变更单。 |
| 退出标准 | G1–G7 全部通过；任何阻塞项均已修复或按制度批准风险接受；具备可执行回滚。 |
| 风险与责任角色 | 缺少远程版本、部署记录或回滚责任人为高风险；发布责任人不得放行。 |

## 8. 发布门禁

| 编号 | 门禁 | 通过证据 | 阻塞条件 | 责任角色 |
| --- | --- | --- | --- |
| G1 | 功能 | UC-01 正向闭环通过；必要角色路径完整 | 关键路径无法完整执行 | 模块 01、业务验收人 |
| G2 | 授权 | UC-02、UC-03、UC-04 服务端拒绝通过 | 仅前端隐藏或缺少 token/范围测试 | 模块 01、安全责任人 |
| G3 | 安全 | UC-05–UC-08、审计和私有附件证据通过 | 状态可跳转、可重复提交、闭环可改或附件越权 | 模块 01、安全责任人 |
| G4 | 性能 | UC-12 的开发者工具和真机记录 | 未测真机、出现可复现卡顿/白屏且无降级 | 模块 03 |
| G5 | 兼容 | 小程序构建、目标端运行、弱网 UC-09 通过 | 构建失败、目标端异常或错误无法恢复 | 模块 01、模块 03 |
| G6 | 日志与审计 | 开发日志、状态审计、变更记录完整 | 日志伪造、审计缺失或可改删 | 模块 01、模块 02 |
| G7 | 履职回归 | UC-13 通过，既有履职功能无回归 | 未验证或发现回归 | 模块 01、业务验收人 |

任何一个门禁无证据、失败或结论为阻塞，发布结论必须为“阻塞，不得进入试运行”。
