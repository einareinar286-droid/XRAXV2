## 3. 本期产品边界

### 3.1 目标

建立安全监察部与市场营销部之间的燃气安全隐患上报、交办、整改、复核与闭环的可验收规格体系，并将登录、角色、部门数据范围、安全、性能、兼容与履职回归纳入同一验收链路。

### 3.2 本期范围

- 隐患 `REPORTED → ASSIGNED → RECTIFICATION_SUBMITTED → CLOSED` 的正向闭环，以及复核退回 `REJECTED`。
- 四类角色、服务端授权、部门/受办范围、私有附件、审计、并发与幂等约束。
- Mock 到 uniCloud/公司 API 的替换边界、测试策略、性能指标与发布门禁。
- UI/交互验收口径，不代替视觉设计或前端实现。

### 3.3 非范围

- AI 审核、订阅消息、送气工画像、未承诺的统计能力或新的业务流程。
- 直接删除隐患。
- 将前端演示角色切换当作生产授权。
- 修改履职领域逻辑、数据库 schema、公共 API、云端配置或视觉实现。

## 6. 潜在风险分析

| 等级 | 风险 | 应对 |
| --- | --- | --- |
| 高 | 错误目录或过期资料导致规格与实际工程脱节 | 接入目标工程后逐项以源码、日志、构建和部署记录复核；差异登记后再更新 Spec |
| 高 | 前端角色切换被误用为生产权限 | 生产授权只接受服务端 token 与部门范围校验；越权用例必须有服务端拒绝证据 |
| 高 | 附件可通过公开或可猜测 URL 访问 | 私有存储、受控下载、附件审计与越权测试作为发布门禁 |
| 中 | 共享规则在多个模块中分叉 | 本文档集与协同规格为规则来源；所有公共变更走变更控制 |
| 中 | 文档被误读为实现完成 | 用“阻塞/待证”标注缺失证据，不允许用需求文本替代测试结果 |
| 低 | 后续文档无法追溯到开发工作 | 每条需求绑定里程碑、预期模块、验收用例、证据和开发日志位置 |
