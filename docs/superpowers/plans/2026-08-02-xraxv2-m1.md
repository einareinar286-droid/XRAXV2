# XRAXV2 M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish a fully tested Mock issue-closure foundation without changing the existing duty cloud behavior.

**Architecture:** A pure issue domain kernel owns state, authorization, validation, concurrency and audit rules. A Mock adapter implements the stable service contract, a thin store handles page state, and uni-app pages consume the service rather than mutating demo memory directly.

**Tech Stack:** uni-app, Vue 3, Vite, Node 22 built-in test runner, JavaScript ES modules.

## Global Constraints

- M1 is explicitly Mock-only and must never be described as production authorization or private storage.
- Preserve `src/services/duty.js`, `uniCloud-aliyun/cloudfunctions/duty-service/` and existing duty schemas.
- Do not publish local agent instructions, prompt files, proxy settings, tokens, keys or `.env` files.
- No new runtime or test dependency.
- Every state mutation validates role, data scope, current state, `version` and `requestId`, then appends one audit event.
