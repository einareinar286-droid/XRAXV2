# XRAXV2 M3 真实数据一期设计

**状态：** EE 已确认方案 1，待审阅本设计后进入实施计划  
**目标：** 在不向 Cloudflare 测试站传输真实人员或业务数据的前提下，建立可迁移到私有服务器的账号、人员、履职、全员仪表盘和简单操作日志基础。

## 1. 范围与边界

本期实现以下能力：

1. 手机号与密码登录；初始密码按手机号生成后只保存密码散列。“记住密码”实现为受控会话续期，不保存明文密码。
2. 本地花名册导入预检、人员暂存、唯一内部员工编号、部门和岗位映射。
3. 员工本人履职任务与内容填报；已提交内容保留历史，不允许他人直接覆盖。
4. 安全监察部和超级管理员查看全公司履职仪表盘，并按部门、人员、统计周期下钻。
5. 简单操作日志，回答“谁在什么时间对什么对象做了什么，结果如何”。

本期不做真实附件公网访问、短信、微信登录、AppID、Cloudflare 真实数据部署、资讯抓取或 AI 审核。Cloudflare 仅继续承载匿名 Mock 演示。

## 2. 已确认业务规则

| 规则 | 设计结论 |
| --- | --- |
| 普通员工履职 | 仅查看、填写和补充本人任务；不能读取全员履职或操作日志 |
| 安全监察部履职 | 查看、筛选全公司履职数据，审核履职任务，读取简单操作日志 |
| 超级管理员（EE） | 拥有安全监察部全公司范围，并可管理正式版人员、账号状态和权限 |
| 市场营销部 | 在履职范围中按普通员工处理，仅查看本人；隐患整改权限沿用既有受办规则 |
| 履职率 | 按期提交且审核通过 ÷ 应履职；目标固定为 100%，无任务显示“不适用” |
| 未达标 | 未提交、待审核、退回、逾期与逾期补交进入考核清单；不使用“良好/一般” |
| 手机号异常或重复 | 暂存为 `PENDING_VERIFICATION`，禁止登录，不自动激活 |

## 3. 导入与身份策略

### 3.1 来源与处理顺序

1. 仅读取本机花名册和履职表；原始 Excel 不进入 Git、Cloudflare、构建产物或日志。
2. 花名册的部门分组向下继承，生成每个人完整的部门、岗位和合同类型映射。
3. 系统为每条人员记录生成不可变 `employeeId`；姓名永远不是身份主键。
4. 手机号统一规范化为数字串，仅符合大陆手机号格式且唯一的记录可进入待激活队列。
5. 重复手机号、异常手机号、同名且无法通过手机号唯一识别的记录进入“待核验”清单，由超级管理员在私有环境处理后激活。
6. 履职汇总按规范化手机号匹配人员；匹配不唯一的记录不自动挂靠到任何账号。

### 3.2 账号状态

```text
PENDING_VERIFICATION  导入成功但手机号重复、异常或人员对应不唯一，禁止登录
ACTIVE                已核验，可登录
DISABLED              离职、停用或人工禁用，禁止登录且保留历史
```

初始密码只在账号初始化动作中使用一次，服务端立即写入密码散列。任何导入报表、操作日志、前端缓存和 Git 提交均不得保存初始密码明文。

## 4. 领域模型与服务边界

页面继续只调用服务层；后端替换时不让 Vue 页面直接读取数据库。

| 模块 | 负责内容 | 核心数据 |
| --- | --- | --- |
| 会话与账号 | 登录、续期、登出、账号状态 | `Account`、可信会话 |
| 人员组织 | 员工、部门、岗位、导入核验 | `Employee`、`Department`、`ImportReview` |
| 履职 | 任务、个人提交、审核、考核 | `DutyTask`、`DutySubmission`、`DutyAssessment` |
| 全员仪表盘 | 公司/部门/人员的统计与下钻 | 只读统计快照 |
| 操作日志 | 业务和管理动作的追加记录 | `OperationLog` |

拟定服务契约如下，尚未写入现有代码：

```text
auth.login({ phone, password, remember })
auth.logout()
auth.getCurrentUser()

personnel.previewImport(source)
personnel.listImportReview(filters)
personnel.resolveImportReview(id, decision)

duty.listMine(filters)
duty.submitMine(taskId, payload)
duty.review(taskId, payload)
duty.getDashboard({ period, departmentId, employeeId })

operationLog.list({ from, to, actorId, action, targetType, cursor })
```

真实后端从可信会话解析操作者，忽略请求体中的 `role`、`department`、`employeeId` 等可伪造字段。

## 5. 履职数据流

```text
花名册（本机）
  → 本地预检与待核验清单
  → 私有后端人员/账号
  → 履职任务分配
  → 员工本人填报
  → 安全监察部审核
  → 公司、部门、人员三级仪表盘
  → 简单操作日志
```

员工提交履职时记录提交版本和时间；审核通过、退回、补充后重提均追加历史。安全监察部可审核，但不可修改员工已提交原文；超级管理员的管理修正必须写入日志。

仪表盘固定显示应履职、按期审核通过、待提交、待审核、退回、逾期和考核人数。每一项能下钻到人员清单；人员清单再进入该人员在选定周期内的任务明细。

## 6. 简单操作日志

日志由后端在成功或拒绝的业务动作后追加，前端只能读取，不提供手工新增/编辑/删除入口。

```text
OperationLog {
  id, occurredAt,
  actor: { employeeId, displayName, department },
  action,
  target: { type, id, label },
  result,
  note
}
```

最小动作集：隐患上报、交办、整改提交、退回、闭环、重开；履职提交、审核通过、审核退回；人员导入、待核验处理、账号重置、角色或状态调整。

日志不保存密码、token、完整附件路径、附件文件、完整履职正文或完整隐患正文。安全监察部和超级管理员可按时间、操作人、动作和对象筛选；其他员工不可读取。

## 7. 部署与数据安全

- 开发：使用匿名或脱敏测试记录运行自动化测试；真实参考 Excel 仅在 EE 本机进行预检。
- 内测：只有私有服务器、私有数据库、备份策略和访问控制就绪后，才导入真实数据。
- Cloudflare：保留静态 Mock 展示，不绑定真实数据接口、不上传附件、不写入人员信息。
- 附件：本期只保留元数据契约；真实 Word、Excel、文本、图片、PDF 后续接入私有对象存储和短期访问凭据。

## 8. 验收标准

1. 唯一且格式正确的手机号可创建待激活账号；重复或异常手机号只进入待核验，不能登录。
2. 员工登录后只能看到自己的履职任务、提交和审核意见。
3. 安全监察部与超级管理员可查看全公司履职总览、部门统计、人员清单和个人明细。
4. 履职率与考核项能从任务和审核记录追溯，且不以“良好”等主观词替代 100% 目标。
5. 每次核心业务或管理操作都会生成一条不含敏感正文的操作日志；普通员工请求日志会被拒绝。
6. 现有隐患状态机、权限、H5 和微信小程序构建不回归。
7. 发布集合不含花名册、履职源表、手机号、密码、`.env`、私有地址或附件。

## 9. 风险与后续决策

- **高风险：** 未完成私有部署前导入真实数据，会违反当前 Cloudflare 测试边界。缓解：导入命令默认只产生本地预检结果，真实写入需私有环境开关。
- **中风险：** 手机号重复或异常导致账号误挂靠。缓解：禁止自动激活，必须进入待核验。
- **中风险：** 履职明细源表为多层表头。缓解：先建立任务字段映射测试，再做任何批量导入。
- **低风险：** 全员仪表盘数据量增加。缓解：后端按统计周期聚合、分页返回人员清单，前端不全量加载明细。
