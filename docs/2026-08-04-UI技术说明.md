# 徐燃安巡 UI 技术说明（评审草案）

**版本：** v0.1 草案  
**状态：** 待 EE 修改/确认  
**对应产品文档：** `docs/2026-08-04-UI产品需求文档.md`

## 1. 当前技术基线

- 框架：uni-app、Vue 3、Vite、SCSS。
- 端：微信小程序优先，H5 宽屏辅助。
- 测试：Node 内置 test runner；当前工作台、导航、履职、权限和隐患闭环均有 Mock 测试覆盖。
- 服务边界：页面通过 `src/services/` 读取隐患、履职、会话和工作台快照，不直接修改 Mock 数据。
- 当前限制：服务实现仍是 Mock，不能替代真实鉴权、服务端授权、数据库审计或私有附件。

## 3. 响应式规则

- `1200px` 以下：使用小程序式单列内容与底部 TabBar。
- `1200px` 及以上：显示 `AdaptiveNavigation` 左栏；页面内容为左侧预留空间后的宽屏工作区。
- 不使用 JavaScript 侦测屏宽来决定权限；屏宽只影响布局，不影响服务端允许的操作。
- 关键表单、卡片、图片证据均允许收缩；不得出现横向滚动承载关键内容。

## 4. 数据与 UI 的边界

页面只使用以下稳定服务契约；后端上线时替换服务适配器，页面和汇总模型不直接读取数据库：

```text
Issue service
getCurrentUser()  listIssues(filters)  getIssue(id)
reportIssue(payload)  assignIssue(id, payload)
submitRectification(id, payload)  reviewIssue(id, payload)
listAuditEvents(id)

Duty service
getCurrentUser()  listMyDuties(filters)  getDuty(id)
submitDuty(id, payload)  reviewDuty(id, payload)
getDutyDashboard(filters)

Workbench service
getWorkbenchSnapshot({ generatedAt })
```

正式版将把履职仪表盘的读取模型扩展为以下参数和返回范围；这只是接口草案，尚未修改现有服务契约或数据库：

```js
getDutyDashboard({ period, departmentId, ownerUid, scope })

// SUPER_ADMIN 与 SAFETY_OFFICER 返回 company、departments、people 和 reviewItems
// EMPLOYEE 与 MARKETING_OFFICER 不返回全员列表，只返回本人任务与本人记录
{
  scope: 'COMPANY',
  period: { type: 'MONTH', start: '2026-08-01', end: '2026-08-31' },
  company: { duePeople, approvedPeople, pendingPeople, reviewPeople, returnedPeople, overduePeople, assessmentPeople, completionRate },
  departments: [],
  people: [],
  reviewItems: []
}
```

简单操作日志使用单独的只读服务契约，日志只在服务端写入；前端不得自行伪造操作人或写入结果：

```text
listOperationLogs({ from, to, actorUid, action, targetType, cursor })

OperationLog = {
  id, occurredAt, actor: { uid, displayName, department },
  action, target: { type, id, label }, result, note
}
```

`listOperationLogs` 仅允许 `SUPER_ADMIN` 与 `SAFETY_OFFICER` 调用。日志记录业务动作和管理动作，不保存密码、会话 token、完整附件地址、附件正文或完整隐患/履职正文。

真实后端接入时，接口返回的用户身份必须来自可信会话；前端提交的 `role`、`department`、`uid` 一律不能作为授权依据。前端隐藏按钮仅改善体验，不能视为权限控制。

## 5. 正式数据模式要求

正式数据模式需增加 `dataMode: 'LIVE'`、数据生成时间和统计周期；Mock 模式必须保留 `dataMode: 'MOCK'` 的醒目标识。

```js
{
  dataMode: 'LIVE',
  generatedAt: '2026-08-04T08:00:00.000Z',
  period: { type: 'MONTH', start: '2026-08-01', end: '2026-08-31' },
  issueMetrics: {},
  dutyMetrics: {},
  priorityItems: []
}
```

上述结构只是接口草案，尚未进入代码或数据库。正式实现前须单独评审：人员表字段映射、账号初始化、密码散列、会话时效、审计保留期、附件加密存储和数据备份。

## 6. 安全限制

- Cloudflare 现有站点仅作公开 Mock 演示，不写入真实姓名、手机号、初始密码、附件和隐患记录。
- 初始密码为手机号是业务要求，但正式版只能保存密码散列；前端、日志、Excel 导入记录和 Git 均不得保存明文密码。
- “记住密码”在正式版实现为受控会话续期，不等于在设备上保存明文密码。
- 附件正式版仅允许 Word、Excel、文本、图片、PDF；由私有对象存储发放短期访问地址，页面不得拼接或保存公开链接。
- 所有交办、整改、退回、闭环、重开和管理修改必须追加审计记录。

## 7. 组件与视觉实现约束

- 延续现有深矿物绿、白色信息卡、细边框与克制阴影，避免再引入第二套设计系统。
- 状态色只承载风险语义：红色=重大/逾期风险，琥珀色=待处置，蓝色=待复核，绿色=已完成。
- 动效限定为 `opacity` 与 `transform`，建议 180–300ms；不动画尺寸和定位属性。
- 页面必须保留加载、空态、失败、无权限、冲突与提交成功反馈。

## 8. UI 变更测试清单

1. 单元测试：工作台指标、待办排序、导航四入口、角色可见性、履职/隐患状态机、全员履职统计、人员范围过滤与操作日志读取权限。
2. 构建：`pnpm test`、`pnpm run build:h5`、`pnpm run build:mp-weixin`、`git diff --check`。
3. 视口：至少核验 375×812、430×932、1280×800、1440×900。
4. 真机：正式上线前在微信开发者工具和至少一台真机走通“上报→交办→整改→复核→闭环”。
5. 数据：LIVE 模式必须抽样核对工作台数字能追溯至明细；不能用 UI 测试替代权限和审计测试。

## 9. 后续研发顺序

1. 先评审并导入花名册、履职表的字段映射，使用脱敏数据完成导入验证。
2. 实现真实身份、角色、部门和受办范围的服务端模型，明确 `SAFETY_OFFICER` 与 EE 的超级管理员拥有履职全公司范围；其他员工仅本人范围。
3. 将隐患、履职服务适配器从 Mock 切换为真实后端，先实现个人填报、全员履职仪表盘和简单操作日志，再补齐权限、审计和并发测试。
4. 工作台改为消费 LIVE 统计快照；核对公司、部门、人员三级履职口径后再调整图表和视觉细节。
5. 选定私有部署环境后，接入私有附件与生产发布门禁。
