# 徐燃安巡 UI 产品需求文档（评审草案）

**版本：** v0.1 草案  
**状态：** 待 EE 修改/确认  
**适用端：** 微信小程序优先，H5 宽屏辅助展示  
**数据状态：** 当前为 Mock 演示；未接入真实业务数据时，任何指标均不得表述为公司实际结果。

## 1. 目标

让四类使用者在不学习系统的前提下完成本职操作：

- 员工：一分钟内完成一次随手拍上报；定位始终可选。
- 市场营销部：清楚知道收到什么整改、何时到期、如何返还安监复核。
- 安全监察部：一眼识别待交办、待复核、重大及逾期事项，完成闭环确认。
- 超级管理员：看到全公司闭环、履职、考核和待办概览；可在正式版本管理人员、权限及数据。

界面既要适合现场快速使用，也要在领导查看时把“风险、责任、时限、下一步”说清楚。不是做华而不实的大屏，数字必须能追溯到真实记录。

## 2. 本轮范围

### 2.1 信息架构

| 一级入口 | 手机/小程序 | H5 宽屏 | 核心目的 |
| --- | --- | --- | --- |
| 工作台 | 底部 Tab 第 1 位 | 左侧导航第 1 位 | 看闭环、履职、考核和待办 |
| 履职 | 底部 Tab 第 2 位 | 左侧导航第 2 位 | 提交本人履职、查看审核状态 |
| 随手拍 | 底部 Tab 第 3 位 | 左侧导航第 3 位 | 全员上报安全隐患 |
| 我的 | 底部 Tab 第 4 位 | 左侧导航第 4 位 | 查看身份、部门、账号与个人设置 |

宽屏在 `1200px` 及以上显示左侧导航；手机与小程序保留原生底部 Tab。非超级管理员不显示身份切换入口；生产版不保留任何前端角色切换能力。

### 2.2 工作台

工作台按“先风险、后任务、再管理数据”组织，包含：

1. **顶部状态区**：明确标明数据状态（演示数据/正式数据）、当前角色和更新时间。
2. **闭环总览**：隐患总数、待交办、待整改、待复核、已闭环、重大隐患；重大和临期事项使用稳定高优先级样式。
3. **履职与考核**：履职率、待审核数、考核项。口径固定为“按期提交且审核通过”；目标值为 100%，不展示“良好”等模糊评价。
4. **重点待办**：按重大、待复核、临期、普通事项排序；每项显示状态、责任部门、期限和下一步责任方。
5. **快捷入口**：按当前权限显示“去交办”“去复核”“查看履职仪表盘”等，不展示无权限的假按钮。

“全球燃气/生产安全资讯”不进入当前开发范围。后续只有接入可核验来源、记录发布时间和来源链接后，才能在工作台增加资讯区；不得用编造新闻填充页面。

### 2.3 随手拍

- 所有人可见、可上报；标题和现场描述必填。
- 定位可选；拒绝定位不影响提交。
- 支持图片证据；正式版再接入 Word、Excel、文本、图片、PDF 的私有附件存储。
- 上报成功后显示编号、当前状态和后续处置归属。

### 2.4 履职：个人填报与全员仪表盘

履职入口必须同时满足“员工能填”和“管理者能看全”的需求，但可见范围随角色收缩：

| 使用者 | 可见内容 | 可执行动作 |
| --- | --- | --- |
| 员工 | 本人履职任务、本人历史填报、本人审核意见 | 填写本人履职内容、上传佐证、提交或按退回意见补充 |
| 安全监察部 | 全公司、各部门及每名员工的履职完成情况和明细 | 查看全量、按部门/人员/周期筛选、审核履职任务；不能改写员工原始填报 |
| 超级管理员（EE） | 与安全监察部相同的全公司范围，并可查看管理操作日志 | 查看全量、处理管理纠错并留痕、管理正式版人员与权限 |

**个人填报页**必须显示任务名称、周期、截止时间、当前状态、填写内容、附件/图片佐证和审核意见。员工只提交自己的内容，提交后原内容只读保留；退回时在原任务上补充并重新提交，不覆盖历史记录。

**全员履职仪表盘**必须支持“全公司 → 部门 → 人员”三级下钻，默认显示当前统计周期，并展示：

1. 应履职人数、已按期审核通过人数、待提交人数、待审核人数、退回人数、逾期人数、考核人数。
2. 公司履职率及部门履职率；目标固定为 100%，未达标只显示差额和考核项，不使用“良好/一般”。
3. 人员清单：姓名、部门、岗位、应履职项、完成项、当前状态、最近提交时间、是否进入考核；点击可进入该人员的履职明细。
4. 筛选：统计周期、部门、人员、任务状态；超级管理员默认有全公司范围，其他管理者仅能看到本部门范围。

安全监察部和超级管理员默认有全公司范围；普通员工（包括市场营销部员工）仅能查看、填报本人履职任务，不设置部门管理者角色或部门级履职看板。

### 2.5 简单操作日志

后台提供一个只读“操作日志”页面，供安全监察部和超级管理员查询；不追求复杂审计平台，只解决“谁在什么时间操作了什么”的问题。

每条日志显示：操作时间、操作人、所属部门、操作类型、对象编号/名称、结果和简短备注。至少记录：

- 隐患上报、交办、提交整改、退回整改、确认闭环、重开；
- 履职提交、审核通过、审核退回；
- 正式版的人员导入、账号重置、角色或权限调整。

日志不展示初始密码、完整附件地址、附件原文件、敏感正文或会话凭据；普通员工和市场营销部员工无操作日志入口。

### 2.6 隐患处置

| 环节 | 可操作角色 | 页面必须说明 |
| --- | --- | --- |
| 上报 | 全员 | 隐患内容、风险等级、位置（可选）、证据 |
| 交办 | 安全监察部、超级管理员 | 受办部门、整改要求、期限 |
| 整改并返还 | 市场营销部受办人 | 整改说明、证据、返还复核状态 |
| 确认闭环/退回 | 安全监察部、超级管理员 | 复核结论；退回必须写明原因 |
| 重开 | 仅超级管理员 | 重开理由和审计留痕 |

任何已提交的原始内容由原提交人保留；其他人不能直接覆盖。超级管理员如需修正，须走明确的管理动作并记录理由。

## 3. 视觉与交互原则

- 主色为深矿物绿，使用白底信息卡和克制阴影；重大隐患仅使用清晰红色语义，不做闪烁、抖动或大面积红色轰炸。
- 领导页面先展示结论，再显示明细；现场页面先展示当前动作，再显示说明。
- 单条待办卡片只保留：状态、标题、责任方、期限、下一步、入口六类信息。
- 加载、无数据、无权限、网络失败、冲突、提交成功必须是不同状态，不能都显示为空白。
- 关键提交按钮固定使用清晰动词，例如“提交上报”“交办市场部”“提交整改并返还复核”“确认闭环”。

## 4. 数据展示口径

| 指标 | 计算口径 | 展示规则 |
| --- | --- | --- |
| 闭环率 | 已闭环数 ÷ 应闭环隐患数 | 无真实数据时仅标注演示，不作为经营结论 |
| 待复核 | 已提交整改、等待安监确认的事项数 | 必须可进入明细 |
| 重大隐患 | 被标记为重大隐患且未闭环的事项数 | 始终高亮，并置于待办排序前列 |
| 履职率 | 按期提交且审核通过数 ÷ 应履职数 | 目标固定 100%；无任务显示“不适用” |
| 考核项 | 未提交、待审核、退回、逾期提交及逾期补交 | 不使用“良好/一般”等替代文字 |

## 5. 验收标准

1. 手机端四个入口顺序为：工作台、履职、随手拍、我的；宽屏端改为左侧导航。
2. 非超级管理员在“我的”页看不到切换身份功能。
3. 任意员工可在未授权定位时成功完成随手拍上报。
4. 员工在履职页只能查看和填报自己的任务；已提交原文不能被他人直接覆盖。
5. 安全监察部和超级管理员能按全公司、部门、人员和统计周期查看完整履职仪表盘与明细；其他员工无全员范围。
6. 全员履职仪表盘可明确区分应履职、按期通过、待提交、待审核、退回、逾期与考核，且履职率口径固定为“按期审核通过 ÷ 应履职”。
7. 安全监察部和超级管理员可查看简单操作日志；普通员工和市场营销部员工不能读取日志。
8. 市场营销部只能看到并整改分配给本部门/本人的事项；提交后状态为待安监复核。
9. 安全监察部确认后才显示闭环；退回必须填写原因。
10. 工作台所有 Mock 指标有醒目的演示标识；正式数据接入后同一位置显示数据时间与统计口径。
11. 375px 宽手机与 1280px 宽 H5 不出现导航重叠、横向溢出或关键操作被遮挡。

## 6. 本轮不做

- 真实短信、微信登录、记住密码和密码找回。
- 真实人员手机号、密码、附件或隐患数据上传至 Cloudflare 测试环境。
- 实时资讯抓取、AI 审核、地图服务和消息订阅。
- 无来源的“安全形势”数据、履职率或闭环率。

## 7. 请 EE 修改确认的内容

1. 工作台顶部是否需要增加公司全称、Logo 或领导口号；如需要，请给出规范文字/图片。
2. 闭环总览是否要固定按“全公司、部门、个人”三级切换，还是一期先只做全公司。
3. 履职任务的周期是否先统一按月，还是保留周/月/专项三种。
4. 正式上线时，市场营销部是否还需要细分为负责人、整改人、审核人三个岗位。
